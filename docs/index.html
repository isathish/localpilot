What it looks like in practice

Captured from LocalPilot v{{ site.version }} in VS Code on a 36 GB Apple M3 Pro, with gpt-oss:20b served by Ollama. Every run, diff and test result is real; nothing is mocked up.

You see every change before it lands

The agent works on a copy of your project in its own git worktree. Click a changed file for a side-by-side diff, then Apply to workspace or Discard. Outside git, every edit is snapshotted and can be undone per file.

Three tasks, three agents, one window

Split the work into tasks and LocalPilot starts an agent for each, in its own tab and worktree. The Agents panel shows what each is doing; pause or stop any of them. When they finish, apply or discard each one's changes.

Commands run where you can watch them

When the agent runs npm test or git log, it does so in a LocalPilot Agent terminal inside VS Code. You see the output live and the agent gets the real exit code. Right-click any terminal to have its output explained or a failed command fixed.

The same agent from the command line

localpilot "add a test…" runs the same agent in your shell, with the same tools, skills, memory and approvals. Answer y, n or always at each prompt, or pass --yes in scripts and CI.

It knows what your machine can run

LocalPilot reads your RAM, CPU and GPU memory and turns that into a model budget. Installed models are marked fits, tight or too big, and tagged with the jobs Auto routing gives them. New ones install from a catalog straight into Ollama, Docker Model Runner or LM Studio.

It learns which models work for you

The Dashboard ranks your installed models per job from how they actually did on your machine: runs finished, tokens per second, errors. Auto routing prefers the ones that perform. Everything is computed from local files.

Features

What's in the box

LocalPilot is built for local models, which are smaller than cloud models. When a model cannot call tools, it falls back to a text protocol. It trims old context so an 8k window still finishes long tasks. And it asks before anything you have marked as risky.

Agent

  • Agent modeReads and searches your project, edits files, runs commands, checks diagnostics and retries when something fails. Asks first for risky actions.
  • Parallel agentsRun several tasks at once, each in its own tab and (in a git repo) its own worktree, so their edits never collide. Pause, steer or stop any of them. Run one task on several models and keep the best result.
  • Review, keep or undoEvery edit is saved first. Diff, keep or revert per file or per session; changed lines are highlighted in the editor.
  • Skills & subagents14 built-in SKILL.md playbooks load when a request needs them. Install more from GitHub in one step. Nine built-in subagents (explore, coder, reviewer, researcher, clarifier, planner, tester, debugger, docs), or write your own.

Models & setup

  • One-click model setupIf no model is found, LocalPilot installs or starts Ollama and pulls a small starter set that fits your RAM and GPU.
  • Model manager & catalogSee what fits your machine, enable or disable models, set a default, remove them, or install from a curated list with a progress bar.
  • Automatic routingImages go to a vision model, completions to the smallest fill-in-the-middle model, Plan mode to a reasoning model. If the chosen model is offline, the next best one answers.
  • Learns which models work for youTracks, on your machine, how often each installed model finishes its runs, how fast it writes and how many completions you accept. Routing prefers the ones that perform, and better picks are applied with an Undo.
  • Huge models with colibriDetects a running colibri server, which streams the experts of models like GLM-5.2 from disk. Memory fit is judged by the part that stays in RAM, and slow disk-streamed models are kept for Plan mode.
  • Finds your serversDetects Ollama, LM Studio, llama.cpp, vLLM, Docker Model Runner, colibri and model servers inside Docker containers, without any settings.

Context & tools

  • Large-context managementEach model gets a token budget. Old tool output goes first, then older turns are summarised, so an 8k-context model still finishes long tasks.
  • Screenshots, images & browser viewCapture a selection, window, screen or web page and let a vision model fix what it sees. A built-in browser view checks your dev server through DevTools.
  • Terminal & CLICommands run in a visible terminal with real exit codes. The localpilot CLI brings the full agent to any shell.
  • Web search & MCPDuckDuckGo, SearXNG, Brave or Tavily search, plus page fetching. Add an MCP server and its tools show up on their own.

Editor & privacy

  • Inline completionsGhost text from fill-in-the-middle models such as qwen2.5-coder, codestral or starcoder2. Works offline.
  • Deep VS Code integrationChat in the sidebar or an editor tab, @localpilot in the built-in Chat view, local models in Copilot's model picker, light-bulb fixes and commit messages.
  • Follows your rulesReads AGENTS.md, CLAUDE.md, .cursorrules and copilot-instructions.md as they are. Nothing to convert.
  • Private by defaultNo account and no telemetry upload. The extension talks to the model servers you list (all localhost by default), the skill index on GitHub and the web tools. You can switch off the last two. Full list.

Trust

Don't take our word for it

Every claim on this page can be checked in a few minutes. Start with these three:

  1. 1
    Turn off Wi‑Fi. Chat, edits, test runs and completions keep working against a local model.
  2. 2
    Open Settings → Providers. Every address is localhost unless you added one.
  3. 3
    Verify the download. Each release has a SHA256SUMS.txt: run shasum -a 256 -c SHA256SUMS.txt.

Open source, one codebase

The extension and the localpilot CLI are built from the same MIT-licensed code. Releases are built and checksummed by a public GitHub Actions workflow, not on a laptop. Maintained by {{ site.author.name }}.

Tested on three operating systems

About 190 automated tests run inside a real VS Code on macOS, Linux and Windows on every push. A further set of end-to-end tests drives a live Ollama model: editing and fixing files, parallel sessions and subagents, isolated worktrees, stopping a run. They run wherever Ollama is available; CI skips them because it has no model server.

The extension only talks to servers you list

No analytics SDK, no account, no update check. Usage metrics for the Dashboard are files in ~/.localpilot/telemetry. This website does use Google Analytics; the privacy page lists exactly what goes where.

You set the approvals

Terminal, file edits, deletes and network access each have an Ask, Allow or Block policy, with Careful, Balanced and Autonomous presets. Every edit is snapshotted first and can be undone.

Every change is written down

The changelog lists what each release added, changed and fixed, including bugs in earlier releases. Problems and questions go to GitHub issues.

Honest about limits

A 7B local model is not as capable as a frontier cloud model, and it will get some multi-step tasks wrong. LocalPilot compensates with retries, a text fallback for tool calls and diagnostics loops. It shows every step, so you can steer or stop it.

FAQ

Common questions

Which models work best?

Automatic setup installs gemma4:e4b (or gemma4:e2b on machines with less memory). It calls tools and reads screenshots, so one model covers agent work and images. With more memory, qwen2.5-coder 14B or 32B, qwen3, devstral, gpt-oss and mistral-small are stronger agent models. For inline completions use qwen2.5-coder:1.5b, starcoder2 or codestral. Settings → Models marks each size fits, tight or too big for your hardware. After you have used a few models, the Dashboard's Model tuning card ranks them by how they actually performed for you.

What hardware do I need?

A 7B model needs about 8 GB of RAM and runs on most recent laptops; 14B to 32B models want 16 to 32 GB. A GPU or Apple Silicon makes responses much faster but is not required. To run very large mixture-of-experts models on modest RAM, use colibri: it streams the model's experts from disk. Expect minutes before the first token and about one token per second, which suits one careful answer rather than a long agent loop.

I have never run a local model. How hard is the setup?

One click. When LocalPilot finds no model, it offers Set up automatically. That installs Ollama (no admin rights needed), downloads a model that fits your RAM and GPU, and configures itself. It starts with a small model so you can begin within minutes; bigger ones are a deliberate upgrade from the catalog.

Does it use one model for everything?

No. It picks per task: a vision model when the turn has images, the smallest fill-in-the-middle model for ghost text, an optional reasoning model in Plan mode, and a small fast model for read-only subagents. If your default is offline, the best available model answers instead. You can pin any of these in Settings → Models → Routing.

Will it change my model settings on its own?

Only within limits, and you can turn it off. With localpilot.models.autoTune on auto (the default), LocalPilot switches a role to another installed model only when several runs show it is measurably better. It never overrides a model you picked by hand unless that model keeps failing, and every change comes with an Undo. Set it to suggest to be asked first, or off.

My model doesn't support tool calling. Does agent mode still work?

Yes. When a model has no native tool support, LocalPilot switches to a text protocol and reads the tool calls out of the model's reply. Results depend on the model, but 7B coder models handle it well.

Does any data leave my machine?

Your code and prompts go only to the model servers you configure, which are all localhost by default. Two optional features make other requests. The skill registry fetches a names-and-descriptions index from GitHub at most once a day (localpilot.skills.autoInstall: off disables it). The web search and fetch tools follow localpilot.approvals.network; set it to ask to approve each request. Dashboard metrics are written to ~/.localpilot/telemetry and never uploaded. See the privacy page for the full list.

How is this different from Copilot's "bring your own key" option?

Bring-your-own-key swaps the model behind Copilot. LocalPilot is a complete agent: the loop, the tools, parallel agents, change review, skills, subagents, screenshots and MCP. It also registers your local models with VS Code's Language Model API, so other extensions can use them too.

Can I use my existing Claude Code or Cursor rules and skills?

Yes. CLAUDE.md (user, parent and project folders, with @imports), AGENTS.md, .cursorrules, .cursor/rules/*.mdc, .claude/skills, .claude/agents and .github/copilot-instructions.md are all read without any changes — and so are .claude/settings.json permission rules and hooks, .claude/commands slash commands and Claude Code plugins. See the Claude Code compatibility guide.
