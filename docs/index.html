What it looks like in practice

These are screenshots of LocalPilot v{{ site.version }} in VS Code with qwen2.5-coder:7b on Ollama. Nothing is mocked up, and you can reproduce each one on your own machine.

You see every change before it lands

LocalPilot keeps a copy of each file before it edits it. Open the Changes panel for a side-by-side diff, then accept or reject file by file. If a whole run went wrong, roll the chat back to an earlier checkpoint.

Three tasks, three agents, one window

Separate your tasks with | and LocalPilot starts an agent for each one in its own tab. The Agents panel shows what each is doing. When they finish, keep or undo their changes independently.

Commands run where you can watch them

When the agent runs npm test or git status, it does so in a LocalPilot Agent terminal inside VS Code. You see the output live and the agent gets the real exit code. Right-click any terminal to have its output explained or a failed command fixed.

The same agent from the command line

localpilot "fix the failing tests" gives you the identical agent in your shell, with the same tools, skills, memory and approvals. Answer y, n or always at each prompt, or pass --yes in scripts and CI.

It knows what your machine can run

LocalPilot reads your RAM, CPU and GPU memory and turns that into a model budget. Installed models are marked fits, tight or too big. New ones install from a short catalog straight into Ollama, Docker Model Runner or LM Studio.

Setup starts with what you already have

On first launch LocalPilot checks the usual ports and Docker containers, lists the models it found and suggests one for agent work. If there is nothing to find, one click installs Ollama and a starter model that fits your hardware.

Features

What's in the box

LocalPilot was written for small, local models. It falls back to a text protocol when a model cannot call tools, trims old context so 8k windows still finish long tasks, and asks before doing anything you have marked as risky.

Agent

  • Agent modeReads and searches your project, edits files, runs commands, checks diagnostics and retries when something fails. Asks first for risky actions.
  • Parallel agentsRun several tasks at once. Each agent has its own tab, status and set of changes.
  • Review, keep or undoEvery edit is saved first. Diff, keep or revert per file or per session; changed lines are highlighted in the editor.
  • Skills & subagentsSKILL.md playbooks load when they are needed — 14 built in, install any from GitHub in one step, and skills from a catalog install themselves when a request calls for one. Nine built-in subagents (explore, coder, reviewer, researcher, clarifier, planner, tester, debugger, docs), or write your own.

Models & setup

  • One-click model setupIf no model is found, LocalPilot installs or starts Ollama and pulls a small starter set that fits your RAM and GPU.
  • Model manager & catalogSee what fits your machine, enable or disable models, set a default, remove them, or install from a curated list with a progress bar.
  • Automatic routingImages go to a vision model, completions to the smallest FIM model, Plan mode to a reasoning model. If the chosen model is offline, the next best one is used.
  • Zero-config, Docker-readyFinds Ollama, LM Studio, llama.cpp, vLLM, Docker Model Runner and model servers inside Docker containers without any settings.

Context & tools

  • Large-context managementEach model gets a token budget. Old tool output goes first, then older turns are summarised, so an 8k-context model still finishes long tasks.
  • Screenshots, images & browser viewCapture a selection, window, screen or web page and let a vision model fix what it sees. A built-in browser view checks your dev server through DevTools.
  • Terminal & CLICommands run in a visible terminal with real exit codes. The localpilot CLI brings the full agent to any shell.
  • Web search & MCPDuckDuckGo, SearXNG, Brave or Tavily search, plus page fetching. Add an MCP server and its tools show up on their own.

Editor & privacy

  • Inline completionsGhost text from fill-in-the-middle models such as qwen2.5-coder, codestral or starcoder2. Works offline.
  • Deep VS Code integrationChat in the sidebar or an editor tab, @localpilot in the built-in Chat view, local models in Copilot's model picker, light-bulb fixes and commit messages.
  • Follows your rulesReads AGENTS.md, CLAUDE.md, .cursorrules and copilot-instructions.md as they are. Nothing to convert.
  • Private by defaultNo account, no telemetry sent anywhere. The extension only talks to the model servers you list (the defaults are all localhost), plus the skill registry on GitHub and the web tools — both of which you can switch off.

Open source

All of it is on GitHub under the MIT license, maintained by {{ site.author.name }}. The extension and the localpilot CLI are built from the same code. Each release includes a VSIX and SHA-256 checksums.

It only talks to servers you list

There is no analytics SDK, no account and no update check. The only outbound traffic goes to your model servers, your MCP servers and the web tools you approve.

Tested against a real model

The test suite runs in a real VS Code with a live Ollama. It has the agent read a file, edit it, run the tests, work in parallel sessions and stop when asked.

You set the approvals

Terminal, file edits, deletes and network access each have an Ask, Allow or Block policy, with Careful, Balanced and Autonomous presets. Edits can always be undone.

Your existing rule files work

LocalPilot reads AGENTS.md, CLAUDE.md, .cursorrules, .cursor/rules, .github/copilot-instructions.md, .claude/skills and .claude/agents as they are.

Small models have limits

A 7B model is not as capable as the big cloud models. LocalPilot works around that with retries, a text fallback for tool calls, diagnostics loops and a nudge to finish, and it shows every step so you can step in.

FAQ

Common questions

Which models work best?

For agent work with tools, start with qwen2.5-coder at 7B, 14B or 32B, or qwen3, devstral, gpt-oss or mistral-small. For inline completions use qwen2.5-coder:1.5b, codestral or starcoder2. For screenshots use qwen2.5vl or gemma3. The catalog in Settings → Models marks each size as fits, tight or too big for your hardware and stars a recommendation.

I have never run a local model. How hard is the setup?

One click. When LocalPilot finds no model it offers Set up automatically. That installs Ollama (through Homebrew, winget or the official script), downloads a coder model that fits your RAM and GPU, and configures itself. It picks a smaller model first so you can start within minutes; bigger ones are a deliberate upgrade from the catalog.

Does it use one model for everything?

No. It picks per task: a vision model when the turn has images, the smallest fill-in-the-middle model for ghost-text completions, an optional reasoning model in Plan mode, and the best available model when your default is offline or disabled. You can pin any of these in Settings → Models → Routing.

My model doesn't support tool calling. Does agent mode still work?

Yes. When a model has no native tool support, LocalPilot switches to a text protocol and reads the tool calls out of the model's reply. Results depend on the model, but 7B coder models handle it well.

Does any data leave my machine?

Your code and prompts go only to the model servers you configure (all localhost by default). Two features make other outbound calls, and both are optional: the skill registry fetches a names-and-descriptions index from GitHub once a day (set localpilot.skills.autoInstall to off to disable it), and the web search / fetch tools ask for approval before every request. Usage metrics for the Dashboard are written to ~/.localpilot/telemetry and never uploaded. There is no account and nothing phones home.

How is this different from Copilot's "bring your own key" option?

Bring-your-own-key swaps the model behind Copilot. LocalPilot is a complete agent: the loop, the tools, parallel agents, change review, skills, subagents, screenshots and MCP. It also registers your local models with VS Code's Language Model API, so other extensions can use them too.

Can I use my existing Claude Code or Cursor rules and skills?

Yes. CLAUDE.md (user, parent and project folders, with @imports), AGENTS.md, .cursorrules, .cursor/rules/*.mdc, .claude/skills, .claude/agents and .github/copilot-instructions.md are all read without any changes — and so are .claude/settings.json permission rules and hooks, .claude/commands slash commands and Claude Code plugins. See the Claude Code compatibility guide.
