## 1.2.0 — 2026-10-26
### Added
- **Claude Code project configuration works as-is.** LocalPilot now reads the same files Claude Code does — from both `.claude/` and `.localpilot/` — so a repository set up for Claude Code needs no changes:
  - **`settings.json` permission rules** (`~/.claude/settings.json` → `.claude/settings.json` → `.localpilot/settings.json` → `settings.local.json`): `permissions.allow / ask / deny` with Claude Code's rule syntax — `Bash(npm run test:*)` (prefix), `Bash(git status)` (exact), `Edit(src/**)` / `Read(.env)` / `Read(~/.zshrc)` / `Read(//abs/**)` (gitignore-style paths; `Read` covers search tools, `Edit` covers writes and deletes), `WebFetch(domain:github.com)`, `mcp__server` / `mcp__server__tool`, `Task`, `Skill`. Our own tool names work too (`run_command(git *)`). `deny` beats `ask` beats `allow`; a matching `allow` runs without the approval prompt, `ask` always prompts, `deny` returns a refusal to the model instead of running. Chained commands (`a && b | c`) must be allowed in every part and are denied if any part is. `permissions.defaultMode` (`acceptEdits`, `bypassPermissions`, `dontAsk`) decides when no rule matches. `/permissions` lists the rules in force.
  - **Hooks** with Claude Code's protocol: `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Stop`, `SubagentStop`, `SessionStart`, `PreCompact` and `Notification` shell commands receive the event as JSON on stdin (`tool_name` uses Claude's names — `Bash`, `Edit`, `Write`, `Read` — with `tool_input.command` / `file_path` / `old_string` / `new_string`); exit code 2 blocks the action and feeds stderr back to the model (a blocked `Stop` sends the agent back to work, bounded), JSON on stdout is honoured (`decision`, `reason`, `continue`, `systemMessage`, `hookSpecificOutput.permissionDecision` / `updatedInput` / `additionalContext`), plain stdout becomes context for prompt and session-start hooks. `matcher` is a regex on the tool name (our native names match too), `timeout` in seconds, `$CLAUDE_PROJECT_DIR` / `$LOCALPILOT_PROJECT_DIR` and `settings.env` in the environment. `/hooks` lists them; `localpilot.hooks.enabled` turns them off for untrusted repositories.
  - **Custom slash commands** from `.claude/commands/*.md`, `.localpilot/commands/*.md` and `~/.claude/commands`: front-matter `description`, `argument-hint`, `allowed-tools` (permission rules in force for that turn), `model`; the body is the prompt with `$ARGUMENTS` / `$1`…`$9`, `@file` inlining and `` !`cmd` `` shell output (only commands the `allowed-tools` permit). Subfolders namespace (`/frontend:component`, also `/component` when unambiguous); plugin commands are `/plugin:command`. They appear in the `/` autocomplete and `/help`, the transcript shows what you typed, and the CLI runs them too (`localpilot "/ship 1.2.3"`, or in the REPL). `/commands` lists them.
  - **Hierarchical `CLAUDE.md`** with `@imports`: `~/.claude/CLAUDE.md` (every project), `CLAUDE.md` in parent folders (monorepos), the project's `CLAUDE.md` / `.claude/CLAUDE.md` / `AGENTS.md` / `.cursorrules` / `.github/copilot-instructions.md` and `.claude/rules/*`, then `CLAUDE.local.md` (personal, git-ignored) — in that order, and `@path/to/file` on a line imports another file (relative to the importing file, `~/` for home; recursive to depth 5; code blocks are left alone). `/memory` lists the files in force.
  - **Plugins**: a folder with `.claude-plugin/plugin.json` bundling `commands/`, `agents/`, `skills/`, `hooks/hooks.json` and `.mcp.json` is picked up from `.claude/plugins`, `.localpilot/plugins`, `~/.claude/plugins` (including marketplace checkouts), `~/.localpilot/plugins` and `localpilot.pluginPaths`; `${CLAUDE_PLUGIN_ROOT}` is resolved in hooks and MCP server definitions, and `enabledPlugins` in `settings.json` disables one.
- **Several models in parallel.** Every run now holds a slot on the model it was routed to, and the router sees those counts live. When a worker (or an *Auto* chat) would land on a model already serving as many runs as it can — one, once the model is known to answer one request at a time, as Ollama does by default — it is routed to a **comparable idle model** instead (same capabilities, similar quality score, at least a third of the parameters, and small enough to sit in memory next to the models already in use), and the worker's lane says so. Nothing comparable → it queues as before. Two workers routed in the same instant cannot both take the last slot: the pick is reserved the moment it is made. Explicit model choices (a chat's model, a model named in `run_subagent` or an agent file) are never swapped; a spread worker whose stand-in stalls is retried on the parent's model; a parent waiting for its workers gives its slot up so its own model is filled first. `localpilot.routing.parallelModels` (default on). The serial-server notice now says that spreading is in effect and offers more slots on that model as the next step.
- **Truthful Auto.** The model picker's *Auto* entry and the *Auto · model* label show the model the router would actually answer with right now (the default if set and reachable, otherwise the best fit), not the first model in the list; each worker lane shows the model that really answers it, including after a spread.
- **Chat history, properly.** *All chats* is now a real history panel: chats grouped by when they were last used (Running · Pinned · Today · Yesterday · Previous 7 / 30 days · Older), a search box that matches titles **and message text** (results show the matching line), and pin / rename / more… / delete on every row with an inline confirmation — chats that are not in the tab bar can be managed without opening them. Keyboard: ↑/↓, Enter, F2 renames, Delete removes. Untouched empty chats are hidden from the history, **New chat** re-uses an empty chat instead of piling up "New chat" entries, and empty leftovers are discarded on startup.
- **Work strip** at the top of every agent turn: what the agent is doing right now (*Reading the code*, *Researching on the web*, *Editing files*, *Coordinating workers*, *Waiting for your approval*…), live counters (steps · files read · searches · files edited · commands · workers) and the elapsed time. When the turn ends it becomes **Worked for 1m 12s · …** and folds the steps away on click; reopened chats rebuild the same summary from the transcript (the turn duration is now stored on the final assistant message).
- **Folded exploration**: consecutive reads/searches collapse into one row — *Read a.ts, b.ts +2 more · Searched 3 times* — that expands to the individual steps, in the main transcript and inside worker traces.
- **Web search cards**: `web_search` results render as link cards (title · domain · snippet) that open in the browser.
- **Model pre-warm** (`localpilot.prewarm`, default on): focusing the composer or switching models loads the model on Ollama ahead of the request, so the first token is not preceded by a weight load. Throttled per model; off while a run is in flight.
- **Edit** on any of your messages: removes that message and the turns after it, keeps the files as they are and puts the text back in the composer so you can rephrase and send again. **Restore checkpoint** stays for when the files should be rewound too.
- **Model maximum context**: `localpilot.contextWindow` accepts `0` (Settings → *Model maximum*) to ask for the largest window the model supports instead of a fixed size — for 128k-class models on machines with the memory for it. The context meter, model picker and model tooltip now show the window the model is **actually given** (e.g. *32k of 128k*), with a hint when the model supports more than the setting allows.
### Changed
- The agent is now asked to **narrate phases**: one short line about what it is about to check or change before each batch of tool calls (in the same message as the calls), to batch independent lookups so they run in parallel, to work in visible understand → plan → change → verify → report phases, and to **research** unfamiliar libraries, APIs and errors with `web_search`/`web_fetch` (citing sources) and keep durable findings with `memory_save`.
- Brief requests (up to ~24 words) whose only matching skill is a loose match now get that skill **preloaded** instead of hinted: the model no longer spends a round trip on `load_skill` before doing the work, and small local models stop stalling after the load. Longer requests keep the hint so the model can judge.
### Fixed
- A worker's `model_request` event was handled as the parent's: it cleared the parent tab's model and could show a bogus *waiting* status. Worker requests now update the worker's own lane (model chip and hover title).
- **Closing and reopening the chat while agents run no longer loses the work in flight.** A re-created chat view (closed side bar or panel, moved to another container, opened as an editor tab, reloaded window) used to come back with a bare transcript: the partial answer, running steps, worker lanes and status were gone until the run ended, and an **approval the agent was waiting on simply vanished** — the run stalled with nothing to click. The host now keeps a bounded, per-run replay of the live stream (text deltas coalesced, large tool results trimmed) and plays it into the new view right after the snapshot, so it shows exactly what a view that stayed open shows: the live turn with its elapsed time, each running tool, every worker and its steps, queued steering messages and the pending prompt. Runs in other tabs are rebuilt the same way, so switching to them shows one copy of their live turn.
- **Switching tabs or reopening mid-run showed every step twice.** The transcript already contained the tool calls the loop had saved so far *and* the live turn drew them again. `session` messages now tell the UI where the turn in flight starts (`liveFrom`); the transcript stops there and the live turn covers the rest — also correct across a mid-run context compaction, which rewrites the message array.
- **Approvals never stall unnoticed.** A prompt raised while the chat was visible and then hidden, closed or moved is mirrored as a native notification (once), with *Allow / Allow for session / Deny / Show chat*; answering from either place closes it everywhere, and **Stop** denies a chat's pending prompts in all views.
- Reopening a view sends the boot snapshot and model list to **that** view only; other open chat surfaces (side bar + editor tab) no longer receive a second `init`/`session` for each reopen.
- **Move Chat To… Panel (and other closed parts) left an empty part.** Moving the Chat view into a part that was closed made VS Code create the pane, focus it and then tear it down again a moment later; LocalPilot took that for the user closing the part and gave up, so the chat only appeared on a second click. The move watcher now tells the two apart (a pane that vanished before its UI booted is VS Code's teardown and is focused again; one hidden or closed after it was visibly up is left alone), *Open Chat* verifies the view actually came up, and the picker names the side each bar is on for your layout (`workbench.sideBar.location`).
- **Context splitting now budgets against the window the model really gets.** Compaction was measured against the model's native window (often 128k) while the request itself was sent with the configured `num_ctx` (32k by default), so on long sessions the server truncated the prompt silently — dropping the system prompt and early turns — before any summary was ever made. One effective window (setting capped by the model) now drives both the budget and the request.
- **Compaction keeps splitting until the history fits.** A single pass kept the last 8 messages verbatim even when a few huge recent tool results alone overflowed a small window; the manager now tightens the verbatim window (8 → 4 → 2 messages, pruning their tool outputs) and summarises again, and never spends a model call re-summarising a history that is already just a summary. Each pass is reported in the transcript.
- Chat UI in narrow sidebars: message actions (Copy / Edit / Restore checkpoint) collapse to icons so the bar never outgrows the bubble, the background-runs bar drops the model chip in favour of the title, and the "steer this agent" / "paused" composer hints use a short form that fits one line.
- A chat's automatic title no longer starts with the attachment or context block the UI prepended (`<attachment path=…>`), and hidden steering messages can no longer become the title.
- Message actions are reachable from the keyboard (they appear when a button in them takes focus, not only on hover); Escape closes an open picker even when focus has left it.
- Stylesheet declares its encoding, so the `·` separators and `…` in the work strip and worker lanes no longer render as mojibake when the host does not pass a charset.
- `run_command` with an **absolute `cwd`** (models routinely pass the workspace root itself) was glued onto the workspace root and failed with `spawn /bin/zsh ENOENT`; absolute paths are now honoured and a missing directory is reported as such.

## 1.1.12 — 2026-10-24
### Added
- **Dashboard — metrics, telemetry and logs, all local.** *LocalPilot: Open Dashboard* (status-bar menu, chat title menu, **Settings → Dashboard**) shows what LocalPilot did on this machine over **Today / 7 / 30 / 90 days / All**: agent runs (done / stopped / failed, subagents), tokens in and out with **tok/s** per model, model calls with retries and errors, tool calls with failure rates, inline-completion acceptance, and how many providers are up — each with a per-day bar chart. Tables break it down by **model** (time to first token and request time as median / p95), **mode** (steps, duration, tools), **tool** (calls, failures, cached hits, share), **provider health** (uptime, last error, probe latency), completions by language, isolated-worktree activity and the most recent problems. A **Logs** card mirrors the *LocalPilot* output channel with level filter, search and live **Follow**, and opens the day's log file. Everything is computed from daily JSONL files in `~/.localpilot/telemetry` that the extension and the CLI share; prompts, file contents and tool arguments are never recorded, and **nothing is sent to a third party**. `localpilot.telemetry.enabled` turns recording off; `localpilot.telemetry.retentionDays` (default 30, `0` = forever) prunes old files. **Export…** saves everything as JSON; **Delete all recorded data…** clears it. The extension API exposes `telemetry.summary(days)` and `telemetry.logs()`.

## 1.1.11 — 2026-10-24
- **Skills work across the whole agent swarm, not just the top-level chat.** Subagents (`run_subagent`, `run_parallel_subagents`, `run_todos_parallel` workers) now inherit the parent's active skills — preloaded, pinned, forced or loaded during the turn — as a `<skill>` block marked *the agent that delegated this task is working with it*, get a strong match on their own brief, honour `skills:` in their agent file, and accept a `skills` array on tasks and checklist items (`manage_todos` too). `load_skill` is now available to every built-in subagent (it is read-only); a subagent without it is told what applies is already in its brief rather than shown an index it cannot act on. Disabled skills are filtered out at every level.

- **A broken side model no longer takes a subagent lane down.** Read-only subagents are routed to a small "fast" model; when that model stalls or cannot be reached, the lane now fails fast (60 s first-token watchdog, no retries) and runs again on the parent's model, the status line says so, and the router keeps automatic picks away from that model for ten minutes so later lanes do not pay the same price. Explicit model choices are never overridden.

### Fixed
- **`run_todos_parallel` no longer duplicates the checklist.** When the model restated pending items as inline `tasks`, the tool appended copies (3, 4, …) and ran those, leaving the originals pending forever; inline tasks that match a pending item by prompt or title now run that item in place.
- **CI on Windows: isolated-worktree smoke checks.** `repoRoot()` returned git's forward-slash (and possibly 8.3 short-name) path on Windows, which never matched the canonical workspace path; it now resolves to the OS-canonical form. The smoke test also pins `core.autocrlf=false` in its scratch repository so worktree checkouts compare byte-for-byte on runners where Git for Windows defaults to CRLF.

## 1.1.9 — 2026-10-24
### Added
- **Model gallery — search and install from every registry your runtimes use.** A new **Settings → Model gallery** page (*LocalPilot: Browse Ollama Model Gallery…*, also in the LocalPilot menu) browses the whole public catalog of each registry, not just the curated list, with one tab per registry a detected runtime installs from: the **Ollama library** (ollama.com), **Docker Hub's `ai/` namespace** for Docker Model Runner, and **Hugging Face GGUF repositories** for LM Studio (`lms get org/repo@quant`) and Ollama (`hf.co/org/repo:quant`) — pick the runtime in *Install to*. Search as you type, filter by capability, sort by popularity / newest / name, page through results. **Choose size** lists every tag with download size (Hugging Face sums a quantisation's files, sharded repos included), context length, inputs, format (GGUF / safetensors / MLX) and age, marked **fits / tight / too big** for this machine, **latest / default** and **installed**; plain sizes come first and other quantisations sit behind *show all*. **Install** pulls through the chosen runtime with live progress and cancel, and the model shows up under Models, in the picker and in routing when done. **Pull by name** accepts anything the chosen runtime's CLI does; references are validated per runtime on both sides. Cloud-only Ollama models are shown but marked not downloadable; the page offers *Start Ollama* / *Install Ollama* when no server is running. The Models catalog links to it.

### Performance
- **Long transcripts no longer weigh on everything.** Collapsed step bodies (file listings, search hits, terminal output, diffs, subagent reports) are built only when a row is first expanded. A 700-message transcript went from 410 000 DOM nodes to 122 000 and renders in ~170 ms instead of ~1 s; switching between two such tabs went from ~800 ms to ~160 ms, settling a finished turn from 1.6 s to 0.3 s.
- **Streaming stays smooth on long answers.** Settled paragraphs stay in the DOM and only the open tail is re-rendered each tick (the whole reply used to be re-parsed several times a second); "stick to bottom" is read from scroll events instead of forcing a layout on every frame; no 200 KB string copies per tick.
- **Parallel workers cannot freeze the view.** Scroll-follow is coalesced to one layout per frame; a burst of 720 worker events that used to lock the panel for 16 s (seven ~2.8 s freezes) now takes ~1.2 s with no freeze longer than a frame or two in real streaming.
- **Extension host does far less per tool result.** The context-window estimate is allocation-free and memoised per message (2 MB history × 40 steps: 777 ms → 13 ms, identical counts); worktree diffs (three `git` subprocesses) are coalesced per session with one in flight instead of spawned on every tool result of every worker; session-list notifications are debounced to 4/s during streaming while new / renamed / pinned chats still notify immediately.
- **Hardening.** Deleting a model times out after 30 s instead of pinning the job on a hung server; malformed or out-of-order agent events and pathological markdown (20 000 `*`, an unterminated fence, a 2 000-item nested list, giant tables) render without errors or stalls.

### Added
- **Dashboard charts and more KPIs.** Besides the six counters, the dashboard now has **Throughput** (completion tokens/s across all calls, with the fastest model), **Turn time** (median and p95 with steps per turn) and **Cache hits** (read-only tool calls answered from the per-turn cache). Below them, real charts drawn from the same local telemetry: **Activity** per day (model calls, tool calls, agent runs, errors), **Tokens** per day stacked prompt/completion, **Generation speed** per day as a line, **Completions** shown vs accepted, **Run outcomes** and **Tool reliability** donuts, and an **Activity by hour** histogram with the busiest hour. A **Subagents** card lists runs, failures, duration and tool use per agent persona, and the worktrees card shows how many runs were isolated. Everything is inline SVG in the theme's chart palette with hover values and real axis labels — no charting library.

### Fixed
- **Settings page usability, end to end.** The section list is a real tab strip: keyboard-reachable (Tab, arrows, Home/End, Enter/Space), announced with `role=tab` / `aria-selected` / `aria-current`, and in a narrow panel the pill strip scrolls the active section into view and shows edge fades where more sections are hidden (previously the active tab could be cut off and the last sections were unreachable without a trackpad). Switching sections starts at the top instead of keeping the previous section's scroll offset; same-section edits keep the position. Provider and MCP cards expand from the keyboard (`aria-expanded`, Enter/Space) with a visible focus ring. Table cards scroll sideways instead of cutting off their last columns — the Delete button on memory notes was unreachable in a narrow panel. A small **Saved ✓** acknowledgement appears in the header after a setting round-trips; invalid numbers are marked `aria-invalid` with a tooltip saying the allowed range and that nothing was saved. Text and number fields no longer save the same value twice (blur plus the trailing debounce). Card footers align with the card's padding, icon-only buttons have labels, remaining inputs have accessible names, and small reset buttons got a 24 px hit area.
- **Ollama installation on Windows.** *Set up automatically* / *Install* now installs through `winget` first (signed package, proxy- and SmartScreen-aware) and only then downloads `OllamaSetup.exe`, which runs with the full silent flag set (`/VERYSILENT /SUPPRESSMSGBOXES /CLOSEAPPLICATIONS …`); success is verified by finding `ollama.exe` under `%LOCALAPPDATA%\Programs\Ollama` or Program Files instead of trusting the exit code, and a failure shows the installer's last lines. Starting the server always uses the tray app (`ollama app.exe`) when it exists — even with `ollama` on PATH, where a bare `ollama serve` collided with the tray app and left a console window open — and waits up to 90 s for a first launch instead of 20 s. Servers bound to `127.0.0.1` are no longer reported down when `localhost` resolves to `::1`: health checks retry on the IPv4 loopback and keep using it. The PowerShell fallback script checks both install locations and cleans up the downloaded installer.
- **Settings panel follows the VS Code theme properly — dark, light and high contrast.** Dashboard sparklines and share bars use the theme's chart palette (`charts.blue` etc.) and no longer inherit the global SVG stroke that drew a grey outline around every bar; light themes get lighter shadows and tints, high-contrast themes get real `contrastBorder` borders on cards, badges, KPIs and toggles with no translucent tints or shadows; native widgets and scrollbars render in the theme's colour scheme; the dashboard tables use a thin scrollbar. The preview harness (`scripts/settings-preview.html`) accepts `?light=1` and `?hc=1` and tags the body like VS Code does.
- **No more duplicated replies.** When a small model announced an action it never took ("Delegated to 2 background workers. I'll report back when they finish.") and the agent loop pushed it to act, the second answer streamed straight onto the first one ("…finish.Understood as:…"). The loop now emits a `nudge` event: the chat dims the retracted sentence under a **retracted** label, explains in one line why the model is being asked again, and the real answer starts in a fresh block — live and when the chat is reopened. A reply that re-announces a hand-off *after* the workers already finished is nudged to report their results instead of being treated as a new claim, and a fan-out that ran counts as work done so the real report is never flagged as a claim. "Understood as: …" is shown as a quiet kicker rather than body text.
- **One kind of "running" instead of seven spinners.** Tabs, the background-agents strip and each worker lane show a small breathing dot; the only spinners left are the **N Working** card and the status line. In-progress checklist items use a filled marker instead of spinning. While workers run, the status line summarises (*2 workers running · 1 done*) and each lane carries its own current step — the same text is no longer shown twice.
- **Worker lanes fit a sidebar.** The agent name, task and current step are laid out as a grid: in a narrow panel the task gets its own line under the agent instead of being squeezed to nothing, and checklist items run with `run_todos_parallel` show their title (not the first 60 characters of the prompt) on the lane.
- **CLI / headless runs can create files again.** `write_file` on a new path failed with `edit.createFile is not a function` outside VS Code; `edit_file` with an empty `old_text` on a file that does not exist now creates it instead of throwing ENOENT, and a non-empty `old_text` on a missing file gets a clear hint to use `write_file`.

## 1.1.8 — 2026-10-24
### Added
- **Isolated worktrees — agents never clobber each other or your open files.** Every agent chat now works in its own copy of the repository (a git worktree under `~/.localpilot/worktrees/`), seeded from your checkout *including uncommitted work*; `.localpilot/worktrees.json` can list setup commands (`npm ci`…) to run in each new copy. The changes panel shows *N files changed in isolated copy* with before/after diffs, **Apply to workspace** (changes land as ordinary uncommitted edits, 3-way merged on conflict, conflicts listed) and **Discard**; the **Agents** panel has the same actions plus *Open Agent's Worktree in New Window*. `localpilot.worktrees.mode` = `always` (default) / `parallel` / `off`; outside git, agents edit directly. Worktrees of deleted chats are cleaned up.
- **Best of N.** Run one task on several models at once (2–8), each isolated; when the last one finishes a notification offers **Compare results**, listing each model with file counts and its answer, and *Apply this result* / *Apply and discard the others*. Also as *LocalPilot: Best of N…* in the palette.
- **Multitask, Debug and Plan the way Cursor does them.** The mode picker now offers **Agent · Multitask · Debug · Plan · Ask**. In **Multitask** you describe the outcome ("Coordinate parallel tasks…"); the coordinator has no file-editing tools, so it must split the work and hand it to background workers (`run_todos_parallel` now takes the pieces inline as `tasks`), shown in the chat as a **N Working · Stop All** card with one row per worker and its current step, then **N Done**. **Debug** reproduces first, fixes the root cause and verifies. **Plan** ends in a **Prepared plan** card — title, summary, the `.plan.md` file saved under `.localpilot/plans/`, the todos — with a **Build** button (⌘↩) that switches to Agent and runs the checklist in parallel. A tool call printed as an argument-only JSON block (`{"tasks": […]}`) is now resolved to the matching tool instead of being lost, and small models get two corrective turns per run instead of one.
- **Settings, CLI and shortcuts for all of the above.** *Settings → Agent & approvals → Isolated worktrees* picks the mode and folder; the CLI gains `--isolate` / `--no-apply` and `/isolate`, `/apply`, `/discard` (a one-shot `--isolate` run applies its result back as uncommitted changes), plus `--multitask` and `--debug`; <kbd>⇧Tab</kbd> rotates the mode in the composer.
- **Multitask launcher redesigned for non-technical users.** *Split the work* / *Try several models* cards, one row per task (Enter adds a row, pasting a list fills several), **Ideas for this project** computed from the workspace (errors VS Code shows, uncommitted changes, missing README/tests, TODO notes, dependencies, recent prompts) with **More ideas** from the model, autocomplete while typing, and a plain-language footer saying exactly what will start. Agents started together form a batch; when the last finishes, **Review results** lists them.

## 1.1.6 — 2026-10-24
### Added
- **Pause, steer and stop — for agents and their subagents.** A **Pause** button (<kbd>⌥Esc</kbd>) sits next to **Stop** while an agent runs: the agent finishes its current model call or tool batch, then holds (*Pausing after this step… → Paused*, ⏸ in the tab, frozen progress bar) until you **Resume**. Anything typed while it is paused — or while it is running, via *Add to this agent* on <kbd>Enter</kbd> — is queued inline as a *queued* row and appended to the conversation at the next step, so you can redirect the agent without losing its work; a message that arrives as the model finishes continues the turn instead of ending it.
