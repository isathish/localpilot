# Changelog

All notable changes to LocalPilot are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/) and the project uses [Semantic Versioning](https://semver.org/).

## Unreleased

## 1.0.0 — 2026-10-23

LocalPilot 1.0 — the local-first coding agent is stable: resilient model calls, a calm and steady chat, built-in skills for the whole development loop, and a release pipeline that ships every push.

### Added
- **Resilient model calls.** Every request to a model server now goes through a retry layer: connection drops, HTTP 5xx/429 and an empty completion are retried up to twice with back-off before you see an error; a stream that produces nothing for 3 minutes (model loading, long prompt) or goes silent for 90 s mid-answer is cancelled as a stall and retried; a server reply that the prompt is too long compacts the conversation once and sends it again. The chat shows *Retrying (1/2) — the model stopped responding* notes and counts the seconds while waiting for the first token; errors are rewritten into one actionable sentence (what failed, what to do) and carry a **Retry** button that replays your last message. New `retry` agent event for other front-ends.
- **Loop and runaway guards.** The same tool with the same arguments more than three times in one turn is refused with a message that tells the model to use the earlier result or change approach; when a turn hits the 40-step limit the agent now says so (*reply "continue"*) instead of ending on a dangling tool call. An empty assistant reply is no longer accepted as the answer.

### Changed
- **Faster turns.** Project rules files (`AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `.cursor/rules/*`, copilot instructions…) are read once and cached until one of them changes instead of on every prompt build; the context budget's history estimate is reused rather than recomputed for every model step; failures are reported once (the agent loop) instead of twice.
- **Version 1.0.0.** Settings, commands and the extension API are considered stable from here; breaking changes will bump the major version.

## 0.2.9 — 2026-10-23
### Added
- **`claude-ui-ux` built-in skill.** A design playbook for calm, warm, typography-led interfaces and for the UX patterns of assistant/agent surfaces — content-first layout, warm neutrals with a single amber accent, generous spacing, quiet motion, streaming replies that never jump, collapsible tool steps, permission prompts with single-key answers, plan panels, honest empty/loading/error states — with a mandatory `browser_inspect` verification pass in both themes and at narrow widths. Loaded automatically for "Claude-like", "assistant UI", "agent UI", "calm/minimal but warm" requests, or force it with `/skill claude-ui-ux`.

### Fixed
- **Provider brand marks in Settings.** The *Add a provider* cards and the configured-provider list now show a two-letter brand mark in each vendor's accent colour (λ for llama.cpp, a plug for custom endpoints) instead of a lone, sometimes lowercase, first letter; long names no longer wrap unevenly.
- **Chat view stability.** Several sources of flicker and lost context in the chat webview are gone: a same-session refresh (mode/model change, compaction, restore) keeps your scroll position, expanded steps and focus instead of rebuilding to the bottom; streaming no longer re-highlights finished code blocks on every tick; agents running in *other* tabs can no longer scroll the transcript you are reading; the Tasks, Changes and background-agents panels update only when their content changes (no spinner restarts, no list scroll reset); popovers close when the transcript scrolls or the view resizes and hand focus back to the composer after a pick. With several permission prompts queued, <kbd>Y</kbd>/<kbd>A</kbd>/<kbd>N</kbd> now answer only the oldest one (previously a single key resolved them all), prompts removed by another view unregister their key handlers, and the reduced-motion mode shows a static "running" glyph instead of an endless spinner.

## 0.2.8 — 2026-10-23
### Changed
- **Every push to `main` releases.** The Release workflow now bumps the version itself when the pushed commits contain anything beyond docs/chore/ci/test housekeeping — patch by default, minor for a breaking `type!:` commit, or the level named in `[release patch|minor|major]` — then commits `release: vX.Y.Z`, tags, builds and publishes. `[skip release]` holds a push back; *Prepare release* and `npm run release` remain for choosing a specific version. Generated release notes now fall back to housekeeping commits when nothing else was pushed.

## 0.2.7 — 2026-10-23
### Added
- **Vague requests are interpreted, not guessed.** Before each turn the request is checked for ambiguity (very short, an action with no object — "clean it up" —, pointing words with nothing selected — "fix this", "the error" —, or an unmeasurable goal — "make it better"). When it is flagged the model receives a hidden snapshot of the active file and selection, open editors, files touched this session, open checklist items, the last turns, Problems-panel errors and uncommitted git changes, and is told to start its reply with *Understood as: …* plus assumptions and only ask (one question, 2–4 options, with a recommended default) when two readings would lead to materially different work. The chat shows a small *Request looks ambiguous … interpreting it* note. The same snapshot is a tool, `gather_context`, for the main agent and every subagent. Setting: `localpilot.autoClarify` (also in **Settings → Agent & approvals → Understanding requests**).
- **Skill recommendations while you chat — and learning which skills you are missing.** Each request is matched against the skill index (name, quoted trigger phrases, description terms); matching skills are suggested to the model (so it loads the playbook on its own) and shown as chips under the turn — click one to force it with `/skill`. LocalPilot also remembers what kinds of requests come up and which skills get used; when the same kind of request recurs three times with no skill covering it, it offers **Create "<name>" skill**, which prefills a prompt for the agent to write `.localpilot/skills/<name>/SKILL.md` from what worked in the project (or **Not now** to stop asking). **Settings → Memory & skills** shows how often each skill was used and lists the suggested skills with the same *Create skill* / dismiss actions; the `@localpilot` chat participant shows the suggestion as a button. State lives in `skill-learning.json` in the extension's global storage (`~/.localpilot/` for the CLI).
- **Split big tasks into checklist items that run in parallel.** `manage_todos` items can carry `agent` + `prompt`; the new `run_todos_parallel` tool runs those items concurrently as subagents, flipping each one *in progress → done* in the Tasks panel (which now shows the delegated agent on the item) while the main agent keeps the dependent steps for itself, then integrates and verifies the combined change.
- **Nine built-in subagents with a shared contract.** `clarifier` (vague brief → *Understood as / Assumptions / Alternatives / Approach / Open question*), `planner`, `tester`, `debugger` and `docs` join `explore`, `coder`, `reviewer` and `researcher`, each with a sharper persona and report format. Every subagent is told it cannot ask the user, so when its brief is ambiguous it gathers context, picks the most plausible reading and states it under *Interpretation*. Names are matched loosely (`review`, `debug`, `test`, `Explore agent`…); an unknown name falls back to `explore` with a note.
- **Automatic routing for subagents.** Read-only subagents (`explore`, `clarifier`, `researcher`) run on the smallest tool-capable model that fits this machine — or the one you pick in `localpilot.routing.fast` (`session` keeps the session model) — so parallel exploration stays snappy; implementing subagents (`coder`, `tester`, `debugger`, `docs`) can be sent to a stronger coding model with `localpilot.routing.coding`. Subagents now inherit the parent's model otherwise, instead of the global default. Both live under **Settings → Models → Routing**, and installed models show an *auto · subagents* badge.
- **Chat tabs that show every agent's state.** The tab strip is now a real multitasking bar: one tab per agent in a stable order (pinned first, then creation order — nothing jumps while agents start and finish), a clear highlighted/underlined active tab, a shimmering *loading* state while the selected chat is being fetched, an orange spinner with an inline **■ Stop** for running agents, a green dot for chats that finished in the background, a pulsing ⚠ when an agent is waiting for approval, and **✕** to close a tab (middle-click / <kbd>Delete</kbd> too). Double-click or <kbd>F2</kbd> renames inline; right-click opens Rename · Pin · Fork · Export · Stop / Clear messages · Close · Delete. Tabs are a proper WAI-ARIA tablist (<kbd>←</kbd>/<kbd>→</kbd>/Home/End) with <kbd>Alt↑</kbd>/<kbd>Alt↓</kbd> to cycle and <kbd>Alt1…9</kbd> to jump; the set of open tabs survives the view being hidden and restored, and overflow collapses into **+N** / **All chats**.
- **Background agents strip.** Agents working in *other* tabs are listed under the tab bar with their live step (*Read utils.ts*, *reviewer: grep_search*…); click to switch, ■ to stop. Approval prompts raised by another tab now say which chat they belong to and link to it.
- **Run tasks in parallel from inside the chat.** The All-chats menu opens a launcher where each line becomes an agent in its own tab (a ` | `-separated draft is split automatically). <kbd>⌘⇧Enter</kbd> / <kbd>Ctrl⇧Enter</kbd> sends the current draft in a **new tab**, and pressing <kbd>Enter</kbd> while the current agent is busy offers *Send in a new tab* instead of refusing.
- **Subagent fan-out rendered as a tree.** `run_parallel_subagents` now shows one host step (*Running 3 subagents in parallel · 1/3*) with a queued lane per task that turns into the child's live card (tool counter, *done* / *failed* badge) as it starts — no more duplicate cards or reports overwritten by the parent's tool result. `run_subagent` nests the same way.
- **Agent transcript redesigned as a step timeline.** Every action is one concise row — *Read* `settingsPanel.ts`, lines 96 to 110 · *Searched* for `state.section` · *Ran* `npm run check-types` with an exit badge · *Opened* a URL — with file chips (language-tagged, click to open) and present-tense labels while a step is in flight. Consecutive edits collapse into *Edited settings.js, 2 other steps +4 −2* and expand to per-file diffs; reasoning becomes a one-line *Thought …* summary (full text on expand). Subagents appear as *agent · task · model* pills whose own tool calls stream underneath as nested rows and fold into *Finished with N steps* plus a collapsible report.
- **Close many tabs at once, and real isolation between parallel agents.** ⌘/Ctrl-click or Shift-click selects several tabs (⌘A selects all focused tabs); ✕, <kbd>Delete</kbd> or the context menu then closes them together — *Close N selected*, *Stop and close all*, *Delete selected chats*. Single-tab menus gained *Close other tabs*, *Close tabs to the right*, *Close finished tabs*, *Stop and close* and *Stop all agents*. Each tab now keeps its own composer draft, attachments, images, scroll position and status line while you switch; the model each agent talks to is shown in the tab tooltip, the background-agents strip and the Agents view. When two chats share the same local model, the waiting one says so honestly — *Waiting for qwen2.5-coder — busy with 1 other chat…* — driven by a per-model in-flight tracker in the agent loop (`model_request` event).
- **Chat history & memory management.** New **Settings → Memory & history** page shows how many chats/messages this workspace stores, their size on disk and the oldest one; `localpilot.sessions.retention` (default 50) prunes the oldest idle chats automatically when a new chat starts (pinned and running chats never count). **Clear Chat History…** (Command Palette, Settings, and the chat's All-chats menu) deletes idle chats with an option to keep pinned ones while running agents keep going. Memory notes are now listed individually with scope, size and age and can be opened or deleted one by one.
- **Built-in skills for the whole development loop.** Thirteen playbooks ship with the extension and are offered to the agent in every workspace: `requirements`, `design`, `new-project`, `implement`, `test`, `debug`, `review`, `refactor`, `ui-design`, `docs`, `deploy`, `ship` and `explore-codebase`. Each is a normal `SKILL.md` (copy it into `.localpilot/skills/<name>/` to customise; a workspace or user skill with the same name wins) and is loaded on demand when a request matches. Toggle with `localpilot.skills.builtin` (also in **Settings → Memory & skills**, where sources now read *built-in / workspace / user*).
- **Project map in every prompt.** The system prompt now carries a compact map of the workspace — top-level folders with file counts and their immediate subfolders, root files and detected stack markers (Node, TypeScript, Python, Go, Rust, .NET, Docker, bundler/test configs…) — so the model knows where things live before its first tool call. Cached and refreshed when files are created or deleted.

### Changed
- **Chat shows what the agent is doing right now.** While exploring, the grouped step reads *Exploring codebase · Reading prompts.ts* / *Searching projectMap* (the files read are listed in the tooltip) and collapses to *Explored codebase · 3 files, 2 searches* when done; between a tool result and the model's next token the typing indicator returns so a turn never looks stalled.
- **Settings page updates in place.** Changing a setting no longer rebuilds the whole page: the header and sidebar are created once, only the control you changed (and anything that depends on it — the approval presets, the *default* badge on installed models) is refreshed, a focused text field keeps focus while its scope badge updates, *Test connection* redraws just that provider's card, and a settings refresh never jumps you back to the section the panel was opened with. Lists (providers, MCP servers, model enable/disable) re-render their section only.
- **Settings → Models no longer flickers while a model downloads.** Progress ticks update the bars and labels in place instead of rebuilding the page several times a second, and the scroll position survives the few full refreshes that remain (job started / finished).
- **Release pipeline.** The Release workflow now tests and packages *before* tagging, so a failing build no longer burns a version; a failed Marketplace or Open VSX publish fails the run instead of passing silently; the VSIX is checked to carry the released version and the run summary lists the release, Marketplace and checksum results. New **Prepare release** workflow cuts a release from the Actions tab (patch / minor / major / custom). `npm run release` can generate changelog entries from conventional commits when none were written, releases a hand-bumped untagged version instead of bumping again, and supports `--dry-run`, `--no-push` and `--no-verify`. New `npm run check:version` (also run by CI and the Release workflow) verifies that `package.json`, `package-lock.json`, `docs/_config.yml` and the changelog section agree and that `@types/vscode` is not newer than `engines.vscode`. CI now also runs for `CHANGELOG.md`, `MARKETPLACE.md` and `docs/_config.yml` changes.

## 0.2.6 — 2026-10-23
### Added
- **Release on push.** The Release workflow now also runs on pushes to `main`: when `package.json` carries a version with no `vX.Y.Z` tag yet it creates the tag, builds, tests, publishes the GitHub Release with the VSIX and pushes to the Marketplace / Open VSX. Bump the version (`npm run release -- patch` or by hand) and push — no manual tagging. Pushes without a version change only run CI and the docs deploy.
- **One-click model setup.** When no local model is found (fresh machine, server stopped, models deleted) LocalPilot offers to set one up: it uses a running Ollama / Docker Model Runner, starts an installed Ollama, or opens a terminal with the platform installer (Homebrew / winget / `install.sh`), then downloads a **smallest-first starter set sized to the machine** — the agent model (`qwen2.5-coder` 7b / 3b / 1.5b / 0.5b by memory budget), a tiny completion model and, with room to spare, a vision model — with progress in the status bar and notification. Available from the chat's "no models" notice, the setup wizard, **Settings → Models** and *LocalPilot: Set Up Models Automatically*; off via `localpilot.models.autoSetup`. Idempotent: installed models are skipped.
- **Hardware profile.** RAM, CPU cores and GPU memory are detected (Apple Silicon = unified memory, NVIDIA via `nvidia-smi`, AMD via `rocm-smi`, Windows via WMI) and turned into a model budget and tier shown in Settings; every model and catalog size is marked **fits / tight / too big**.
- **Model manager** (**Settings → Models**, *LocalPilot: Manage Models*): runtimes (Ollama, Docker Model Runner, LM Studio) with running / installed state and *Start* / *Install* for Ollama; installed models with size, capabilities and routed roles; per-model **enable / disable** (`localpilot.models.disabled` — hidden from pickers, routing and status bar, kept on disk); *Set default*; **Remove** for Ollama and Docker Model Runner models; live job list with progress and cancel.
- **Model catalog**: 14 curated families (Qwen2.5 Coder, Qwen3, Devstral, gpt-oss, Llama 3.1/3.2, Gemma 3, Qwen2.5 VL, Mistral Small 3.2, DeepSeek-R1, Codestral, StarCoder2, Phi-4 mini, SmolLM2) with every size, approximate footprint, roles and a ★ recommended size per family for this machine. **Install to** Ollama (`/api/pull`), Docker Model Runner (`docker model pull`) or LM Studio (`lms get`) with inline progress; filter by role, search; commands *Install Model from Catalog…*, *Remove Local Model…*, *Enable / Disable Model…*.
- **Automatic routing** (`localpilot.routing.enabled`): turns with images go to a vision model when the session model cannot see (`localpilot.routing.vision` or best installed — for that turn only); inline completions use the **smallest** FIM model that fits; Plan mode can use a reasoning model (`localpilot.routing.reasoning`); an offline or disabled model falls back to the best available one with a status line explaining why. Ranking weighs tools / FIM / vision, family, size and whether the model fits in memory. The status bar shows the model that will actually answer and download progress while pulling.
- Ollama discovery now records each model's on-disk size and parameter count; extension API gains `autoSetupModels()` and `installModel()`.
- **DevTools inspection for web pages (`browser_inspect`).** A dependency-free Chrome DevTools Protocol client drives the headless browser and returns, in one tool call, the screenshot plus the **console** (logs, warnings, errors and uncaught exceptions with `file:line:col`), the **network trace** (every request with status, type, size and timing — failed ones listed), **performance** (DOMContentLoaded, load, FCP, LCP, DOM nodes, JS heap) and **layout checks** (horizontal overflow with culprit elements, images without alt, tiny text, unlabelled controls). Optional `actions` (`click`, `type`, `scroll`, `eval`, `wait`) reproduce a flow before capture. The report renders as a DevTools panel in the chat (status chips, colour-coded console with clickable locations, failed requests, metrics) and is exactly what the model reads; the system prompt tells the agent to inspect after web UI changes. `browser_screenshot` now also goes through DevTools (real load event, true full-page capture) and reports the error/failed-request counts, falling back to a plain CLI capture when needed. Camera menu → *Inspect a URL…* and *LocalPilot: Inspect a Web Page…* attach the screenshot and draft the report into the composer; `inspectUrl()` joins the extension API.
- **Browser view & web-page screenshots.** Two new agent tools: `open_browser` shows a URL in VS Code's built-in Simple Browser beside the editor (or the system browser), and `browser_screenshot` renders a URL — including `localhost` dev servers — with a headless Chromium already on the machine (Chrome, Chromium, Edge, Brave, Arc; `localpilot.browser.chromePath` to override) at desktop, phone (`mobile`) or tall (`full_page`) viewports. With a vision model the PNG is attached to the conversation so the agent can verify its own UI changes (the system prompt asks it to); with a text-only model the image is still shown in the transcript. Screenshots appear inline in the tool step (click to enlarge). Also available to you: camera menu → *Screenshot a URL…* / *phone size* / *Open URL in browser view…*, commands *Screenshot a Web Page…* and *Open URL in Browser View…*, and `screenshotUrl()` on the extension API.
- **Richer chat rendering.** Fenced code is syntax-highlighted (JS/TS, Python, shell, Go, Rust, C-family, Java/Kotlin/Swift, SQL, Ruby, PHP, JSON, YAML/TOML, HTML/XML, CSS, Markdown, diff) with colours taken from the editor theme; a fence like ```` ```ts src/api/client.ts ```` shows the file name as a clickable link, and blocks show their line count. Markdown gains nested lists, task lists (`- [x]`), inline images, bare-URL autolinks and `~~~` fences. Tool results render by kind: **read_file** as a numbered, highlighted listing with a clickable header; **run_command** with **ANSI colours/bold** (escape sequences stripped), a line count, *Copy command* and *Copy output*; search/diagnostics results with clickable `path:line`; **web_fetch**/subagent results as Markdown with the source link; pending tools show their arguments as a key/value table. Images in user turns and Markdown open in a **lightbox** (click, Esc, copy to clipboard). User messages render inline code and file links.

### Changed
- **One-click install in the setup wizard.** When no server is found, the wizard shows a single button for the situation — *Install Ollama & starter model* (Ollama missing), *Start Ollama & download starter model* (installed but stopped) or *Download starter model* — with the exact models and download size (e.g. "Qwen2.5 Coder 7b + 1.5b, ≈ 5.7 GB") and the installer used (winget / Homebrew / install.sh). Clicking it runs the whole thing without a confirmation dialog, shows live progress in the wizard, and jumps to the model step with the starter model pre-selected when done. Ollama is **installed by LocalPilot itself, in the background, without admin rights**: the official build is downloaded with byte-level progress and installed user-side — macOS `Ollama-darwin.zip` → `/Applications` (or `~/Applications`, quarantine cleared); Windows `OllamaSetup.exe /VERYSILENT` (per-user); Linux `ollama-linux-<arch>.tar.zst` decoded with Node's built-in zstd (`.tgz` fallback) into `~/.local/share/localpilot/ollama`, then `ollama serve` — no `sudo`, no systemd, works in WSL. The interactive terminal script (Homebrew / winget / `install.sh`) is only a fallback if the background install fails. No confirmation dialog anywhere: *Set up automatically* in the chat and the wizard button go straight to install → start → download → configure, with a cancellable progress notification. Ollama is found at its install location even before it is on `PATH` (Windows `%LOCALAPPDATA%\Programs\Ollama`, Homebrew, `/usr/local/bin`), the Windows tray app is started correctly, and a fresh install that auto-starts the server is detected immediately.
- **Settings → Models** replaces *Models & generation*: machine card (hardware, budget, runtimes with Start / Install), activity list, installed models, Routing, Generation and the catalog on one page. Rows wrap as units on narrow panels, badges share one height whether or not they carry an icon, progress bars use the brand accent, and the page was verified in light and dark themes at 480–1400 px. The *Inline completions* page points to Routing for the completion model; the chat's "no models" notice and the setup wizard lead with **Set up automatically**.
- Docs: new *Automatic setup*, *Managing models* and *Automatic routing* sections with screenshots, updated Getting started, Troubleshooting (missing models, wrong model answering, download failures), Configuration (routing / models settings), the Ollama / LM Studio / offline guides, the landing page (features, steps, FAQ), `llms.txt` and the walkthrough.

- **Chat UI polish**: a consistent design system for the webview — one type scale (13 / 12 / 11 px, tabular numerals for stats), unified radii (6 / 8 / 12 px), theme-derived soft borders and tint layers instead of hard-coded greys, and LocalPilot's amber used sparingly as the brand accent (empty-state tile, progress bar, thinking step, running tab, task in progress, context ring). Cards (diff, terminal, approvals, Tasks, Changes) share the same header height, hover states and shadows; approvals use a left accent instead of a loud full border; exit codes are pills; keyboard hints render as key caps; the composer has a softer focus ring, borderless context chip and a rounded-square send button; popover and toasts match. - **Settings UI polish & responsiveness**: the Settings / setup webview now shares the chat's tokens (type scale, radii, soft borders, tint layers, brand accent) — unified card, badge, toggle, segmented-control and field styling with a soft focus ring; installed-model rows, activity jobs and catalog variants align in grids with consistent control widths; on narrow panels the sidebar becomes a scrollable pill bar under a compact sticky header, the hardware card, routing fields, catalog rows and setup footer reflow to one column, and nothing overflows horizontally. Includes a settings preview harness (`scripts/settings-preview.html`) for checking light/dark and widths.
- **Smarter code search**: `file_search` and `grep_search` now state clearly that one matches file names and the other file contents; an empty `file_search` for a bare identifier points the model at `grep_search`/`find_symbol`; and a shared *Using tools* section in the system prompt (all modes) tells the model to search contents to locate code, read before answering, and try another tool before concluding something does not exist. Fixes small models giving up with "no file named `compute_total`".
- **Completion nudge**: when an agent-mode run ends with a bare "done"/"fixed" to an action request without having called a single tool, LocalPilot pushes back once (hidden steering message) so the model performs the action instead of claiming it; loaded skills now end with an explicit execute-now instruction and `/skill` spells out load → perform → report. Fixes small models occasionally answering "done" and doing nothing.
- **Approvals you can't miss**: when a permission prompt is raised while the chat view is hidden (background tab, closed sidebar, CLI/API-started agent), it is mirrored as a VS Code notification with *Allow / Allow for session / Deny / Show chat*; answering in either place resolves it.
- **More real end-to-end tests** against a local model: read → understand → `edit_file` of an existing file (other functions untouched), ask-mode workspace understanding (finds the file defining a symbol using read-only tools only), the active editor attached as context, **skill-based execution** (a workspace `SKILL.md` is discovered, loaded via `load_skill` and its instructions followed), and **parallel subagents** (`run_parallel_subagents` fans out two real `explore` children that each read their own file; both reports come back merged and the parent summarises them).
- **Multi-tab parallel streaming verified**: a stateful mock-controller harness (`scripts/ui-preview-parallel.html`) drives two sessions streaming at once — each tab keeps its own live transcript, switching tabs mid-stream shows the right in-flight text and tool steps, a session finishing in the background clears its spinner without disturbing the visible one, and reopening a finished tab renders the stored transcript with no stale live node.

## 0.2.4 — 2026-10-23
### Added
- **Zero-config auto-detection of model servers.** At startup and on *Refresh models*, LocalPilot probes the configured providers, the well-known local ports (Ollama, LM Studio, llama.cpp, vLLM, **Docker Model Runner** `12434`, Jan, SGLang, KoboldCpp) and **running Docker containers** (`docker ps` — Ollama, vLLM, llama.cpp, LocalAI, TGI, SGLang, model-runner, KoboldCpp images, using each container's published host port). Every reachable server that isn't configured yet is added to `localpilot.providers` automatically (existing entries are never changed) and a notification says what was found. If the configured default model is offline, LocalPilot uses the best available one and offers to make it the default.
- **Docker-based models**: a *Docker Model Runner* provider preset (`http://localhost:12434/engines/v1`, models like `docker/ai/qwen2.5-coder`), container discovery as above, and a one-click **Enable** prompt when the Model Runner is active but host (TCP) access is off. The setup wizard lists Docker servers too and marks newly found ones.
- MCP client tests that launch a real stdio MCP server and round-trip a tool call, and verify that an un-launchable server fails fast with its error shown in **Settings → MCP servers** ("failed to start" badge with the reason).
- `@localpilot` / Language Model API: image attachments (`LanguageModelDataPart`) are forwarded to vision models instead of being dropped; non-image attachments are inlined as text.

### Changed
- MCP servers that cannot be spawned (bad command, missing `npx`) fail immediately instead of hanging 30 s; on Windows they are launched through the shell so `npx`/`.cmd` launchers resolve.

## 0.2.3 — 2026-10-23
### Added
- **Settings screen** (*LocalPilot: Settings*, gear icon in the chat toolbar): a dedicated panel for every option — **Providers** (add from presets for Ollama, LM Studio, llama.cpp, vLLM, Jan, LocalAI, SGLang or a custom endpoint; edit URL/key/context/models; enable/disable; *Test connection* shows latency and the live model list), **Models & generation**, **Agent & approvals** with *Careful / Balanced / Autonomous* presets, **Inline completions**, **Web search**, **Memory & skills** (skill folders, discovered skills and subagents, open/clear notes), **MCP servers** (add/edit/remove, connection status and tool counts) and **Advanced**. Each value shows whether it comes from User or Workspace settings and can be reset individually; a scope toggle chooses where edits are written.
- **Welcome / Setup wizard** (*LocalPilot: Welcome / Setup*): detects running model servers, lists their models with a recommended default, and picks an approval preset and inline completions. Opens automatically on first run when no server is reachable (`localpilot.showWelcomeOnStartup`).
- **Getting Started walkthrough** in VS Code's Welcome page; commands *Manage Model Providers…* and *Clear Memory Notes…*; the Agents view and the chat's "no models" notice link straight to setup/providers.

- Deep links `vscode://localpilot.localpilot-agent/settings?section=…` and `/setup`, and matching `localpilot --settings` / `--setup` CLI flags.
- Integration tests (`npm test`, real VS Code) covering the settings panel commands, provider probing against an Ollama-style server, input sanitisation and configuration round-trips.
- **Real end-to-end tests** against a local Ollama server (skipped when none is running): the agent writes a file through a real tool call, two sessions run **in parallel** and each finishes its own task, and `stop()` aborts a streaming run. Tests run in a fresh temporary workspace folder.
- **Extension API** (`vscode.extensions.getExtension('localpilot.localpilot-agent').exports`): `runPrompt`, `runParallel`, `send`, `stop`, `getSession`, `runningSessionIds`, `onDidChangeRuns`, `listModels`, `version` — drive LocalPilot agents from other extensions or scripts.

### Fixed
- **Tool calls printed as text are now executed.** Small models (e.g. 1.5B coders) often emit `{"name": …, "arguments": …}` as plain text instead of using the tool channel; the agent loop now parses fenced, tagged and bare JSON calls for known tools whenever no native call arrives, so the run continues instead of stopping with a dead answer.
- `write_file` reports a clear error when given a directory path (such as `.`) instead of a raw filesystem failure; the system prompt now states how paths are resolved and that tools must be invoked, not described.
- Versions are no longer hard-coded: the MCP client advertises the real extension version, `package-lock.json` is bumped by the release script and the docs refer to `X.Y.Z` instead of a stale number.

### Changed
- "Open settings" in the chat and the no-model fallback now open the LocalPilot Settings panel instead of the generic VS Code settings editor.
- Finishing the setup wizard merges newly detected servers into `localpilot.providers` instead of replacing the list; MCP server entries are validated before being written; the first-run wizard never replaces a Settings panel the user already opened.

## 0.1.4 — 2026-10-23
### Added
- **Persistent memory**: the agent saves and recalls durable notes (`memory_save` / `memory_read` / `memory_list` / `memory_delete`) in `.localpilot/memory/` (project, commit-able) and global storage (user). A compact index is injected into every prompt; *LocalPilot: Open Memory Notes* opens the folder.
- **Planning checklist**: `manage_todos` tool and a live **Tasks** panel with progress bar; the agent plans multi-step work first and updates each step as it goes. Plan mode now emits the checklist too.
- **`localpilot` CLI**: *Install 'localpilot' Command in PATH* writes a shim so `localpilot "fix the tests"`, `--plan`, `--ask`, `--file`, `--parallel` start agents in the current folder via a `vscode://` URI handler.
- **Multitasking tab strip** in the chat view: running sessions first with spinners, `+` to start another agent in parallel.
- **Loading & streaming UI**: top progress bar while running, typing indicator before the first token, streaming caret, shimmer on running tool steps, *Thought for Ns* timer.
- `localpilot.thinking` levels `off|on|low|medium|high` (Ollama `think`, OpenAI `reasoning_effort`); `localpilot.keepAlive` keeps the Ollama model loaded between turns; `localpilot.memory.enabled`.
- Website: **Ask AI** buttons on every docs page and in the footer — open ChatGPT, Claude, Perplexity or Gemini (Google AI Mode) with a page-aware prompt pre-filled; **Copy page as Markdown** and **View as Markdown** on docs pages; `/llms.txt` index for LLM crawlers.
- Website: full footer with Product, Documentation, Guides, Works-with and Community columns, a Topics strip linking every target keyword, and privacy/trademark notices.

### Changed
- **Caching**: identical read-only tool calls are served once per turn (including concurrent duplicates) and show a *cached* badge; mutating tools invalidate the cache. `@workspace` file tree is cached with file-watcher invalidation.
- **Context**: the prompt now carries the session's working set (files read/edited) and current checklist, so compaction no longer loses track of progress.
- Website: Google tag (gtag.js) now loads whenever `google_analytics` is configured (previously only in the `production` Jekyll environment) and reports `ask_ai`, `click_install`, `download_vsix`, `click_github` and `copy_markdown` events.

## 0.1.0 — 2026-10-23

Initial public release.

### Added
- **Providers**: Ollama (native API) and any OpenAI-compatible server (LM Studio, llama.cpp, vLLM/SGLang, Unsloth GGUF, LocalAI, Jan, OpenRouter…) with automatic model discovery and capability detection.
- **Agent / Ask / Plan modes** with streaming, tool calling, approval gates, and a prompt-based tool protocol for models without native function calling.
- **Tools**: file read/edit/write/list/delete, ripgrep search, symbol & reference lookup, shell commands, diagnostics, web search (DuckDuckGo, SearXNG, Brave, Tavily), web fetch, ask-user, skills and subagent delegation.
- **Parallel agents**: concurrent sessions, *Run Tasks in Parallel*, Agents panel with live status, bounded parallel tool execution and `run_parallel_subagents`.
- **Change review**: per-session file snapshots with Diff / Keep / Undo and editor line highlights.
- **Large-context management**: token budgeting, tool-output pruning, LLM compaction, context meter.
- **Skills & subagents** (`SKILL.md`, `.localpilot/agents/*.md`), compatible with `.claude/` and `.github/skills` layouts; built-in `explore`, `coder`, `reviewer`, `researcher`.
- **Project rules** auto-loaded from `AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `.cursor/rules`, `.github/copilot-instructions.md`, `.localpilot/rules.md`.
- **Context mentions**: `@workspace`, `@selection`, `@problems`, `@git`, `@editors`, files, line ranges, folders; drag-and-drop attachments.
- **Screenshots & images** for vision models: OS screenshot capture, paste, drag-drop, picker, Explorer menu.
- **Editor integration**: inline edit (`⌘⌥K`), terminal command generation, light-bulb Fix/Explain actions, context-menu actions, commit-message generation, FIM inline completions.
- **VS Code platform**: `@localpilot` chat participant, Language Model Chat Provider (local models in Copilot's picker), status-bar model switcher.
- **MCP** stdio client exposing server tools to the agent.
- Multi-session persistence with fork, pin, rename, export.
