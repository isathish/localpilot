All notable changes to LocalPilot are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/) and the project uses [Semantic Versioning](https://semver.org/).

## Unreleased

## 1.5.6 — 2026-11-05

### Added
- **Self-healing: LocalPilot verifies its own work and fixes what it broke.** After the agent changes files in Agent, Debug or Multitask mode, LocalPilot runs your project's checks. If a build, type-check, lint or test fails, it finds the root cause, applies a targeted fix and runs the checks again. It stops when the task is verified or a limit is reached, and then tells you why it stopped and what to do next. It is on by default in VS Code and the CLI, for the agent, its subagents and skills. `localpilot.healing.enabled` (default on) turns it off, and setting `localpilot.healing.autoFix` (default on) to off makes LocalPilot only detect and report failures. See [Self-healing & recovery](docs/docs/self-healing.md).
- **Checks are found automatically and run only when needed.** LocalPilot reads your project files to find the build, type-check, lint and test commands for Node/TypeScript, Python, Go, Rust, Maven, Gradle, .NET and Make projects, including packages in a monorepo. Nothing runs while it looks. Checks run only after a turn changed code, whether through the edit tools, commands such as `sed -i` or code generators, or subagents. Edits to docs, images and other files no check covers do not start them. By default they run once when the agent says it is done (`localpilot.healing.checkTiming`, default `onComplete`), and the tests affected by the change run first (`localpilot.healing.scopeTests`, default on). A quick type-check and lint baseline (`localpilot.healing.baseline`, default `fast`) separates failures that were already there from new ones, so the agent is not blamed for old failures and does not try to fix them. Add, replace or turn off checks in `.localpilot/checks.json` or `localpilot.healing.checks`. In an untrusted workspace, `.localpilot/checks.json` and workspace settings are ignored, but your User settings still apply. In the CLI, pass `--trust-workspace` to use them.
- **Failures are recognized, not just reported.** Output from TypeScript, ESLint, Jest, Vitest, Mocha, node:test, Python (pytest, mypy), Go, Rust, Maven/Gradle, .NET, npm, pip and git is turned into a named failure (compile, lint, unit or integration test, runtime, dependency, database, git conflict, security, data corruption, permission, model or tool) with a stable key such as `TS2345@src/api/user.ts`. Failures with the same cause are grouped into one. Each kind of failure gets its own treatment. A model server that is down is retried with backoff after checking that it is back. A model that runs out of memory is retried with a smaller context. A malformed tool call is repaired without asking the model again. Git conflicts, data corruption and permission errors go straight to you.
- **Diagnose, fix, run again, with limits for each kind of failure.** Each fix attempt gets the failing output, the relevant code and this turn's changes, and the agent must name the root cause. Code failures get up to `localpilot.healing.maxRepairAttempts` attempts (default 3), with at most `localpilot.healing.maxTotalAttempts` (default 8) per task, `localpilot.healing.extraSteps` (default 16) extra model steps, a recovery deadline (`localpilot.healing.taskDeadlineMinutes`, default 60, counted only while a recovery is running) and `localpilot.healing.checkTimeBudgetSeconds` (default 900) for one round of checks. If the same error survives two attempts, LocalPilot stops and asks you instead of trying again. With `localpilot.healing.delegateFixes` (default on), independent failures can be fixed by parallel fixer subagents, with one heavy check running at a time.
- **Fixes that make things worse are undone.** After a fix passes, the full relevant test suite runs again (`localpilot.healing.regressionRequired`, default on) to make sure nothing else broke. A fix that adds failures, or breaks a check that passed before, is rolled back to the exact earlier file contents, and the next attempt is told what went wrong. Failures from other tasks running at the same time are not blamed on the fix. Each attempt records the files it changed and can be rolled back later, newest first. Files you edited in the meantime are left alone.
- **Every task ends with an outcome you can trust.** Answers end with a footer such as 'Verified: typecheck ✓ · tests 42/42 ✓' or 'Incomplete: `npm test` still fails … after 3 attempts', with the root cause and the next step. The outcomes are Completed, Not verified, Incomplete, Blocked, Failed and Cancelled. **Not verified** means nothing failed but a required check could not run: it was denied, timed out, no checks were found, or the worktree has no installed dependencies. A task is also Not verified if a fix changed the tests or check scripts that judge it, and the footer lists those changes.
- **A recovery card and a queue for problems that need you.** Each recovery shows one card in the chat that updates as it runs. The card shows the attempt ('Self-healing · attempt 2/3 · TypeScript (TS2345)'), the phases, the root cause, a ✓, ✗ or ⏱ result for each check, and the files each attempt changed. It ends as Recovered, Not verified or Needs you. Depending on the problem, it offers Resume, Retry with guidance, Approve install, Rollback, Open merge editor, Accept risk and Dismiss. Problems waiting for you are collected in a human intervention queue, which you can open with **LocalPilot: Show Human Intervention Queue**. They also appear in a 'Needs attention' group in the Agents view. **Open Recovery Report**, **Resume Recovery** and **Roll Back Self-Healing Fixes** are in the Command Palette.
- **CLI exit codes, `--require-verified` and NDJSON.** One-shot `localpilot` runs exit `4` when the task is incomplete and `5` when it is blocked. `0` still means completed or not verified, so add `--require-verified` to make Not verified exit `4` as well. Recovery steps print as notes (attempt N/M, root cause, check results), and a turn that ends unfinished prints an Incomplete, Blocked or Not verified block with the root cause and the commands to run next. With `--json`, `run_result` includes the `outcome` and `contract`, `finishReason` can be `incomplete` or `blocked`, and `recovery` events are written as NDJSON lines.
- **New task queue statuses: `incomplete` and `needs_input`.** A queued task that ends Incomplete is marked `incomplete`. One that is waiting for your approval, credentials or a conflict review is marked `needs_input`. Tasks that depend on either one wait, as they do after a failed task. **Retry** continues in the same chat from where the recovery stopped. Queued tasks never install anything, and they run checks only when no approval prompt is needed.
- **Recovery continues after a restart.** Reloading or closing the window, or closing the terminal, pauses a running recovery instead of cancelling it. When you reopen the chat, a Recovery interrupted card offers Resume, Rollback fixes and Dismiss. Resume runs the checks again first and never repeats an edit or an install. A queued task cut off by a reload continues in its own chat. In the CLI, `localpilot -c` shows the interrupted recovery with the command to resume it. In the REPL, `/recovery status | resume | rollback [attempt] | history | dismiss` works on the current chat. `localpilot recovery list | show <id> | resume <id> | clear [id]` manages the interrupted recoveries of every session in the folder. Only one window or CLI process works on a recovery at a time. Stop and Ctrl+C still cancel.
- **LocalPilot remembers failures and the fixes that worked.** When a failure comes back, up to two earlier fixes are offered to the agent as suggestions to check against the current code. They are never applied automatically, and a suggestion that keeps failing stops being offered. Secrets are removed before anything is saved. `localpilot.healing.memory` sets where this is kept: `workspace` (default, on your machine only), `project` (`.localpilot/recovery-memory.json`, which you can commit to share and which is read only in a trusted workspace) or `off`.
- **Self-healing in Settings and on the Dashboard.** Settings → Agent & approvals → Self-healing covers every `localpilot.healing.*` setting. It includes a Retry configuration table for attempts, waits and time limits per kind of failure (`localpilot.healing.policies`) and a list of the checks found in the open workspace, with an **Open checks.json** button that creates the file from a template. Settings → Dashboard → Self-healing & recovery shows failures detected and recovered, recovery rate, mean time to recover, the problems waiting for you and the recovery running in each chat. It has eight views: Failure History, Root Cause Analysis, Recovery Attempts, Applied Patches, Retry Configuration, Regression Reports, Human Intervention Queue and Recovery Performance Analytics. OTLP export adds the `localpilot.recovery.events`, `localpilot.recovery.outcomes` and `localpilot.recovery.duration_ms` metrics. Recovery telemetry holds only categories, outcomes, counts, timings and a hashed failure key, never code, messages or file paths.
- **Self-healing never gets around your approvals or security.** Check commands go through the same permission rules, hooks, approvals and audit log as the agent's own commands. With `localpilot.approvals.terminal: ask`, one prompt approves a turn's checks for up to 30 minutes, and you are asked again if the agent changes the scripts behind them. Installing a dependency always asks, even with `approvals.terminal: always`, and unattended runs report Blocked instead of installing. `localpilot.healing.dependencyInstall` (default `ask`, User settings only) set to `never` turns installs off. Destructive commands always ask while a recovery is running, including in subagents. Git conflicts are always handed to you (`localpilot.healing.gitConflicts`: `escalate`). Before a task completes, `localpilot.healing.securityCheck` (default `changed`) scans the changed files offline for secrets and risky code. It can only be set in User settings, so a repository cannot turn it off, and only you can accept the risk of a finding. That decision needs confirmation and is audited.

### Fixed
- **A one-shot CLI run stopped by the system now saves its chat.** When a one-shot `localpilot` run is stopped by SIGTERM or SIGHUP (for example, a closed terminal or a cancelled CI job), it now saves the chat before it exits.
- **Correct exit codes for runs stopped by a signal.** A one-shot run stopped by SIGTERM now exits with `143` and one stopped by SIGHUP with `129`, instead of `130`.
- **A fix that only swaps one failure for another no longer counts as fixed.** If a fix attempt replaces a failure with a new one of the same kind, from the same check and in the same file (for example, the same unit test failing with a different message), the attempt is now recorded as not fixed. The retry budget now runs out as it should, and the dashboard no longer counts the task as recovered.
- **Ollama stopping in the middle of a run is now retried.** When Ollama stopped during a run, the "No local models found" error was treated as an unknown, fatal failure. It is now treated as the model being unavailable, so recovery waits, retries (starting a stopped local server when it can) and offers **Start server** if it is still down.
- **Recovery saves no longer get lost on Windows.** On Windows, a recovery-state save, a patch rollback or a failure-memory write could be dropped while the same file was being read (by the CLI, another VS Code window, an antivirus or an indexer). These writes now retry for a moment, so the save always lands.

## 1.5.4 — 2026-11-05

### Fixed
- **Agents started together each get their own isolated copy.** In a parallel batch or Best of N, two agents creating their git worktree at the same moment could collide on git's locks; the one that lost silently edited the workspace directly instead of working isolated. Worktrees are now created one after another per repository (setup still runs in parallel), with retries when another git process holds a lock.
- **Saving `.mcp.json` no longer restarts its MCP servers.** When the file was read while being saved (empty for a moment) or with a syntax error, its servers were treated as removed and stopped, then started again once the save finished. A file that cannot be read keeps the servers it had until it reads cleanly again; the syntax error is still reported.
- **MCP servers are not restarted when their script is only read (Windows).** With `localpilot.mcp.watchServerFiles`, Windows reports a file being read as a change, so starting one server could restart every other server that uses the same script, and a server could keep restarting itself. A restart now needs the script's size or modification time to change.
- **Reading PDFs works on Windows.** `read_pdf`, PDF attachments and password-protected PDFs failed on Windows because the pdf.js data folders were passed with backslashes, which pdf.js rejects.
- **Unsaved edits are measured correctly on Windows.** Keeping or undoing an agent's change in a file with unsaved editor edits counted the disk copy instead of the editor's text, because VS Code reports drive letters in lower case and the paths never matched; the editor highlights for tracked changes had the same mismatch.

## 1.5.3 — 2026-11-04

### Added
- **A built-in Markdown Reader.** Open any `.md` file in its own LocalPilot Markdown Reader tab with Open With… or **LocalPilot: Open Markdown Reader to the Side**, read two documents side by side, and get your reader tabs back after a window reload. The 'Aa' reading-settings popover (key `a`) sets column width, font, line height and text size, and your choice applies at once to every open reader.
- **Diagrams, math and more in the Markdown Reader.** Mermaid diagrams are drawn offline (with Copy source, Copy SVG and Save SVG), and math, GitHub alerts, footnotes, a front-matter Properties table, sticky table headers and an inline `[[toc]]` are rendered. ### Changed
- **The CLI ignores risky project settings unless you pass `--trust-workspace`.** Providers, MCP servers, approvals, hooks and other security-sensitive settings in a project's `.vscode/settings.json` are no longer applied by the terminal CLI on their own, and it tells you which ones it ignored.
- **Hook, approval and auto mode settings come only from your user settings.** A repository's `.vscode/settings.json` could switch hooks back on, loosen approvals or turn on auto mode. These settings are now read only from your user settings (and `~/.localpilot/config.json` in the CLI). Changing them while Settings is on the Workspace scope now saves them to User settings instead of failing.
- **`localpilot -p` and piped runs keep stdout clean and never stop to ask.** Approval prompts, questions, pickers and errors now go to stderr, so stdout contains only the answer. Actions that need approval are denied with a note to pass `--yes`, and the agent's questions get its recommended answers. Input piped into `localpilot "<prompt>"` (for example `git diff | localpilot -p "review this"`) is now sent to the model with the prompt instead of being dropped.
- **Answering "always" approves only that kind of action.** In the CLI, [a]lways used to approve every kind of action for the rest of the process. It now covers only that kind of action (commands, file edits, network calls), never deletes or destructive commands, and resets on `/clear`. `--yes` is the only way to approve everything. In the chat, "Allow for session" used to work like "Allow once"; it now stops asking for that kind of action for the rest of the chat and approves other waiting requests of the same kind.
- **The CLI is stricter about its arguments.** Unknown options and invalid `--fail-on` values now fail with exit code 2 instead of being treated as part of the prompt or replaced with `high`, and `--option=value` and `--` work. `localpilot scan` fails for a folder that does not exist, and exits with code 2 when OSV.dev fails partway through (after one retry), listing the advisories it could not fetch, instead of passing a CI gate.
- **The CLI moves deleted files to `~/.localpilot/trash`.** Files the agent deletes in the terminal can now be recovered, and the approval says where they go. Undo and Restore checkpoint now bring back deleted files in VS Code too. In Remote-SSH, WSL and containers, where there is no trash, files are deleted permanently and the approval says so.
- **The CLI uses the same settings as your VS Code.** It now reads LocalPilot settings from a non-default profile and from Insiders, Cursor, VSCodium or Windsurf, not only the default VS Code Stable profile, and `localpilot.repos` now works there.
- **Cmd+Shift+E (Ctrl+Shift+E) opens the Explorer again.** With text selected it used to start a LocalPilot Explain run. That shortcut is gone; Explain is still in the editor's right-click menu.

### Security
- **Shell permission rules can no longer be bypassed.** Commands chained with a lone `&` or `|&`, or hidden in `$(…)`, backticks, `<(…)` or Windows `%VAR%`/`!VAR!`/`@(…)` expansions, are now seen: an allow rule asks you instead of approving the extra command, and a deny rule blocks it. `Bash(git status:*)` no longer matches `git statusfoo`.
- **Instruction files can no longer pull secrets into the prompt.** `@import`s in AGENTS.md, CLAUDE.md and rules could read any file on the machine, such as `../` paths or `~/.ssh` keys. Imports are now limited to the workspace and Markdown under `~/.claude` and `~/.localpilot`, credential files such as `keys.json` and `.credentials.json` are never imported, and a refused import stays as plain text. Entries in `.localpilot/repos.json` or `localpilot.repos` that point at the filesystem root, your home folder or a parent of the workspace are ignored.
- **Organisation policy is enforced fully.** Approvals the policy requires are asked every time; `--yes`, [a]lways and "Allow for session" no longer skip them. `LOCALPILOT_MANAGED_SETTINGS` can no longer replace a policy file installed in the system location, and a project's deny rules still apply when the policy only asks. With `disableBypassPermissions` on, `permissions.defaultMode` `"dontAsk"` still works, and `"dontAsk"` now refuses only actions that would have asked.
- **Auto mode always asks before risky commands.** Windows and PowerShell recursive deletes, `git reset`/`clean`/`checkout`/`restore` with options in a different order, deleting the `.git` folder, and shell commands that touch secret files like `.env` used to run without asking.
- **Plan, Ask and Multitask modes no longer offer MCP tools that can change things.** Only MCP tools the server marks read-only are available there.
- **`vscode://` LocalPilot links from elsewhere ask first.** Links that did not come from the `localpilot` command now ask before starting an agent or running a terminal command, and can only attach files inside the workspace.
- **Plugins are safer to install.** A marketplace entry can no longer run git options hidden in its ref, sha or URL, or delete folders outside the plugins folder with a name like `..`. Plugins listed in a Claude Code marketplace catalog under `~/.claude/plugins` are no longer all treated as installed and enabled (with their hooks and MCP servers running); only plugins Claude Code actually installed are loaded.
- **Permission rules are read and matched correctly.** Rules with globs or absolute paths (for example `Read(./secrets/**)` or `Read(//etc/**)`) were mangled when settings files were read, so deny rules could be lost. Rules now also match MCP servers with an underscore in their name and plugin servers named the Claude Code way (`mcp__plugin_<plugin>_<server>`), and `Task(agent)` rules apply to parallel subagent runs.
- **Pushes and commits do only what you approved.** `git_push` refuses a branch that contains LocalPilot's internal worktree snapshot commit, pushes to the branch's existing upstream and shows the exact destination before asking. `git_commit` with a list of files commits only those files, leaving your own staged files out; when it stages everything, the approval says so and lists new and untracked files first.
- **API keys are kept apart and out of plain text.** Keys entered in workspace settings no longer overwrite user keys with the same provider id, and cleanup no longer deletes keys other workspaces still use. The Brave or Tavily web search key now lives in your OS keychain instead of `settings.json`.
- **Remote images in replies no longer load by themselves.** An image in a model reply that points to a web address now appears as an "Image: <host>" link you click to open.

### Fixed
- **Chat Actions in the Agents view act on the chat you clicked.** The "…" button on a row opened the menu for the chat on screen instead, so Delete removed the chat you were working in, with its isolated worktree and unapplied changes. It now acts on that row's chat, and Delete and Undo all ask first.
- **Stop really stops.** Remaining planned edits and commands are reported as not run instead of running anyway, and nothing is auto-approved after Stop. Stopping during compaction leaves the history as it was and sends no further request; stopping a parallel checklist run puts unfinished items back to pending; Stop also ends a wait for Ollama to start and the creation of an isolated worktree at once, removing the half-made copy. Stop All pauses the task queue and offers to resume it, and a stopped queued task is marked cancelled.
- **Messages are no longer lost.** Messages typed while the agent is finishing, compacting or after an error are sent as the next turn (or put back in the composer if you stopped). Sending during a manual compaction no longer starts two runs or shows a false error, and Clear, Edit, Restore checkpoint and Retry wait for compaction to end. When no model could be selected, the prompt and error now stay in the chat so Retry can send it again.
- **Restore checkpoint and Undo revert the right files.** After a chat was compacted, cleared or edited, Restore checkpoint reverted the wrong files and claimed success even when nothing changed. It now reverts the files changed since that message, or says none were recorded, and is hidden in isolated chats, where it did nothing. The report compares models on pass rate, time, steps, tool calls, tool errors and tokens, shows the change since the last run, and lists why each task failed. Projects add their own suites in `.localpilot/evals/*.json`. It exits with 1 on a failure, so CI can gate on it. First result on this machine: Gemma 4 12B passed 3 of 8; the failures were mostly timeouts after repeated empty replies and stalls from the model, which is now measurable. See [Benchmarking models](docs/docs/terminal-and-cli.md#benchmarking-models).
- **Pull requests and CI from the chat.** `/pr` commits the current changes on a new branch (after running the checks that cover them), pushes and opens a pull request with a description; `/fix-ci` reads the failing GitHub Actions checks, reproduces the failure, fixes it and pushes. The agent also has the tools behind them: `git_status`, `git_commit`, `git_push` (never forced, refuses the default branch unless you ask), `pull_request` (create, view, list, comment) and `ci_status` (runs, the log lines of failed steps, re-run). Pull requests and CI use the GitHub CLI. Commits ask like edits, pushes, comments and re-runs like terminal commands, and in Ask and Plan mode only the reading actions are available. With Gemma 4 12B, "commit my change on a new branch and push it" produced the branch, a conventional commit and the push in one run.
- **Organization policy.** Administrators can deploy `managed-settings.json` to a system location (`/Library/Application Support/LocalPilot/` on macOS, `/etc/localpilot/` on Linux, `%ProgramData%\LocalPilot\` on Windows), and users and projects cannot override it. It can always block or always ask for actions (same rule syntax as `settings.json`), set an approval floor per kind of action, turn off bypass modes and Auto mode, cloud providers (or allow only listed hosts), web access, MCP servers not on a list and skill downloads, and write every tool call and approval to a JSON Lines audit log. A policy that cannot be parsed fails closed. Users see it in Settings, `/permissions` and `localpilot doctor`. Also fixed along the way: an `ask` rule on a tool that never prompts by itself (`Read(.env)`) let the call run without asking; it now asks. See [Organization policy](docs/docs/configuration.md#organization-policy).
- **Repository graph.** A new `repo_graph` tool builds an import graph and a symbol index straight from the source (TypeScript/JavaScript, Python, Go, Rust, Java/Kotlin, C#). It needs no language server, so it works in the CLI too, and it re-reads only changed files: this repository's 144 files index in 38 ms. Ask "what breaks if I change `src/util.ts`?" and the agent lists every file that imports it, directly or through others, and the tests to run. It also finds where a symbol is defined, the most-imported modules, import cycles and which files use a package. With Gemma 4 12B, an impact question that a text search answered wrongly (one file found, "no tests") is now answered correctly in one tool call. See [Context](docs/docs/context.md#repository-graph).

### Fixed
- **Auto picks the stronger model again.** Auto gave a name-based bonus only to Gemma 4 and Nemotron, so a smaller Gemma 4 outranked a bigger model with the same capabilities (for example `gemma4:12b` over `qwen3.8:27b` on a 36 GB Mac). ### Changed

- **Closing and reopening the chat while agents run no longer loses the work in flight.** A re-created chat view (closed side bar or panel, moved to another container, opened as an editor tab, reloaded window) used to come back with a bare transcript: the partial answer, running steps, worker lanes and status were gone until the run ended, and an **approval the agent was waiting on simply vanished** — the run stalled with nothing to click. The host now keeps a bounded, per-run replay of the live stream (text deltas coalesced, large tool results trimmed) and plays it into the new view right after the snapshot, so it shows exactly what a view that stayed open shows: the live turn with its elapsed time, each running tool, every worker and its steps, queued steering messages and the pending prompt. - **Switching tabs or reopening mid-run showed every step twice.** The transcript already contained the tool calls the loop had saved so far *and* the live turn drew them again. `session` messages now tell the UI where the turn in flight starts (`liveFrom`); the transcript stops there and the live turn covers the rest — also correct across a mid-run context compaction, which rewrites the message array.
- **Approvals never stall unnoticed.** A prompt raised while the chat was visible and then hidden, closed or moved is mirrored as a native notification (once), with *Allow / Allow for session / Deny / Show chat*; answering from either place closes it everywhere, and **Stop** denies a chat's pending prompts in all views.

- **Move Chat To… Panel (and other closed parts) left an empty part.** Moving the Chat view into a part that was closed made VS Code create the pane, focus it and then tear it down again a moment later; LocalPilot took that for the user closing the part and gave up, so the chat only appeared on a second click. - **Context splitting now budgets against the window the model really gets.** Compaction was measured against the model's native window (often 128k) while the request itself was sent with the configured `num_ctx` (32k by default), so on long sessions the server truncated the prompt silently — dropping the system prompt and early turns — before any summary was ever made. One effective window (setting capped by the model) now drives both the budget and the request.
- **Compaction keeps splitting until the history fits.** A single pass kept the last 8 messages verbatim even when a few huge recent tool results alone overflowed a small window; the manager now tightens the verbatim window (8 → 4 → 2 messages, pruning their tool outputs) and summarises again, and never spends a model call re-summarising a history that is already just a summary. Each pass is reported in the transcript.
- Chat UI in narrow sidebars: message actions (Copy / Edit / Restore checkpoint) collapse to icons so the bar never outgrows the bubble, the background-runs bar drops the model chip in favour of the title, and the "steer this agent" / "paused" composer hints use a short form that fits one line.
- A chat's automatic title no longer starts with the attachment or context block the UI prepended (`<attachment path=…>`), and hidden steering messages can no longer become the title.
- Message actions are reachable from the keyboard (they appear when a button in them takes focus, not only on hover); Escape closes an open picker even when focus has left it.
- Stylesheet declares its encoding, so the `·` separators and `…` in the work strip and worker lanes no longer render as mojibake when the host does not pass a charset.
- `run_command` with an **absolute `cwd`** (models routinely pass the workspace root itself) was glued onto the workspace root and failed with `spawn /bin/zsh ENOENT`; absolute paths are now honoured and a missing directory is reported as such.
- Windows: `//C:/…` absolute permission rules match drive paths, and `${CLAUDE_PLUGIN_ROOT}/file` in plugin hooks and MCP definitions resolves with native separators.
- The post-move watcher stops as soon as the chat UI has booted in its new container, so closing that part right after a move is never undone.

## 1.0.0 — 2026-10-23

### Added
